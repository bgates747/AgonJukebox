# AMP-001 — Evaluate agonAMP and reusable tracker-music hooks

Evaluate agonAMP as a stock-Agon music player before proposing changes to
Jukebox. Start with a small set of downloadable music examples, demonstrate
playback in a dedicated Pi5 emulator, then qualify hardware, then document
integration hooks reusable by Jukebox, AgonWolf3D and Nurples. Preserve upstream
behavior and existing application scheduling; reuse APIs already provided.

## Ordered work

1. **Publish this task first.** Commit this specification and its TODO entry;
   push successfully before cloning, fetching samples, building or running tests.
   Record the commit and selected baseline in private working notes.
2. **Acquire and understand the standalone player.** Clone/pin agonAMP, read
   its build/install instructions, establish supported file formats, stock
   firmware requirements, controls, dependencies and available player/library
   interfaces. Reproduce the existing player; keep speculative redesign out.
3. **Acquire a small music fixture set.** Inspect zxart's search/results and
   download interfaces; retrieve a few samples in formats actually supported
   by agonAMP. Prefer varied small files that exercise different supported
   formats/features. Record title, composer, format, source/download URLs,
   attribution/license when provided, byte size and SHA256. Keep raw samples
   local; do not perform a bulk archive crawl or silently substitute converted
   WAVs for the native formats under evaluation. Bundled upstream examples
   may supplement the site samples and must be identified separately.
4. **Prove standalone emulator operation on Pi5.** Build an ARM64-compatible
   runtime/profile using the established emulator setup workflow. Install the
   unchanged agonAMP application and sample files in a dedicated virtual SD.
   Pin exact MOS/VDP/runtime identities. Verify launch, sample loading, playback
   progress, controls, stop/exit, and repeat launch. Distinguish silent state
   checks from captured audio/listening evidence. Provide review commands and
   expected behavior if human listening is required; leave GUI launch to the
   Author. Record unsupported cases, timing, memory/resource limits and failures.
5. **Qualify hardware next.** After a working emulator fixture, prepare a
   separate /mystuff/agonamp installation and an on-card readme with exact
   invocation, controls and expected results. Deploy when the test card is
   available; back up any existing agonAMP leaf in the workspace, preserve
   Jukebox/logger/autoexec/music, flush writes and leave the card mounted.
   Obtain actual hardware playback/control feedback; do not infer it from the
   emulator. Do not flash firmware as a side effect of deploying the player.
6. **Research integration after standalone/hardware qualification.** Trace
   the actual upstream playback API and design the smallest reusable boundary.
   Document initialization/loading, start/pause/stop, looping, service/tick or
   interrupt requirements, completion/error reporting and complete teardown.
   Inventory RAM/code/VDP buffers, channels, vectors/timers, UART and filesystem
   ownership. Address coexistence with Jukebox's blocking keyboard/timer design,
   WAV playback and game rendering/sound effects. Prefer existing upstream
   entry points. Propose a shared assembly include/library or bounded adapter
   appropriate to Jukebox, AgonWolf3D and Nurples; do not silently integrate or
   redesign those applications in this evaluation.

## Acceptance and evidence

1. Exact upstream revision, requirements and reproducible build/install steps.
2. Small attributed sample inventory with direct sources and hashes.
3. Repeatable Pi5 emulator results and honest audio/listening status.
4. Separate hardware results on identified stock MOS/VDP versions.
5. A concrete integration contract grounded in inspected upstream symbols and
   resource/timing behavior, with remaining questions/limitations stated.

Each stage records what was actually exercised. If a later stage awaits the
Author's card or listening feedback, prepare its complete reviewable fixture
and report that dependency. Do not claim hardware acceptance, continue into
unapproved application edits, or replace tracker playback with pre-rendered
PCM merely to obtain a passing demonstration.
