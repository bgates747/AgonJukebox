# Shading and lighting possibilities

Recorded 2026-09-10 at the Author's request. These are options for discussion,
not selected treatments or authorization to start another experiment. The
current vector checkpoint remains the four-element white-shape pilot 02.

## Available approaches

| Effect | Mechanism | Possible use in this artwork |
| --- | --- | --- |
| Linear gradient | Multiple color stops along a chosen direction | Column highlights, gold rails and straight metallic surfaces |
| Radial gradient | Circular or elliptical fill with adjustable focus | Rounded caps, jewel highlights and localized illumination |
| Mesh gradient | Deformable patches with independently assigned colors | Complex curved surfaces requiring more control than a linear/radial fill |
| Shape-following bevel | A bevel filter or deliberately constructed inset bands | Light and shadow faces following irregular contours, button surrounds and ornament |
| Drop or inner shadow | Offset, color, opacity and optional blur | Raised controls or recessed panels |
| Directional lighting | Diffuse and specular filters operating on a height field | Consistent broad shading and metallic highlights across elements |

Inkscape documents [linear/radial gradients](https://inkscape-manuals.readthedocs.io/en/latest/creating-gradients.html),
[mesh gradients](https://inkscape-manuals.readthedocs.io/en/1.1/creating-a-mesh-gradient.html)
and [drop/inner shadows and filter editing](https://inkscape-manuals.readthedocs.io/en/latest/filters.html).
The installed Inkscape 1.2.2 filter collection at
`/usr/share/inkscape/filters/filters.svg` was inspected: it includes Matte Bevel,
Combined Lighting, Basic Diffuse Bump and Basic Specular Bump. Their definitions
use diffuse/specular lighting with distant or point sources. These shading
filters have not yet been tested on our pilot assets.

Diffuse lighting provides broad surface shading; specular lighting provides
concentrated shiny highlights. SVG defines distant, point and spot sources and
derives surface orientation from a height field. The intended rounded, beveled
or flat geometry must still be supplied; the filter cannot infer it from our
white mask. See the [SVG lighting specification](https://www.w3.org/TR/SVG11/filters.html#feDiffuseLightingElement).

## Shape-following control

A mesh can be shaped by the author, but it does not automatically express a
constant distance from an arbitrary contour. For regular bevel width, consider
explicit inset bands or a distance-to-boundary height field. Direction-dependent
light and shadow can then distinguish the faces. This is a proposed approach,
not a claim that Inkscape has a dedicated distance-gradient fill control.

Use widths expressed in final screen pixels. Narrow regions, holes and sharp
corners need inspection because offsets can collapse or intersect. Preserve the
existing shapes and use separate candidates for any geometry adjustment.

## Agon palette and automation

SVG fills and filter definitions can be generated by scripts and rendered
through Inkscape's command line. Headless path simplification and PNG export
already work in our pilot; gradient/lighting parameters still need their own
bounded visual test.

Agon-colored gradient stops alone do not constrain the interpolated colors.
Antialiasing, blur and lighting can also introduce additional colors and partial
alpha. Two candidate approaches are:

1. Render smooth shading, then deliberately map each material to a chosen ramp
   within the Agon palette, without dithering.
2. Construct explicit bands or bevel faces using only selected Agon colors,
   then enforce palette and coverage at final rasterization.

The first may preserve more subtle lighting; the second gives direct control
over band placement and width. Neither is selected yet. Evaluate saved native
pixels, especially contour cleanliness and surviving gaps. SVG file size or
path count alone does not demonstrate VDP memory or UART savings. Runtime
bitmap packaging remains AGNB.
